# Як перевіряти модель для нової тези

## Що не варто робити як основну перевірку
Не варто брати лише ті самі 144 точки, на яких модель навчалась, і показувати помилку на них як головний результат. Це корисно як демонстрація узгодження, але не як сильний доказ узагальнення.

## Що варто показати

### 1. In-sample evaluation
- Модель прогнозує всі 144 точки.
- Дає красиві parity plots і гістограми похибок.
- Це можна використати для рисунків типу "ANSYS vs ML".

### 2. Random holdout (80/20)
- Частину точок прибираємо з навчання.
- Показує базову узагальнювальну здатність.

### 3. GroupKFold by r
Це головна перевірка для тези.

Ідея така:
- всі точки з одним конкретним значенням `r` вилучаються з навчання;
- модель вчиться на інших радіусах;
- потім прогнозує всю серію комбінацій для невідомого радіуса.

Тобто модель реально перевіряється на інтерполяцію по геометричному параметру, а не просто на запам'ятовування таблиці.

## Які метрики використовувати
Для кожного з `Ky` і `Kz`, а також сумарно:
- MAE
- RMSE
- R²
- MAPE (%)
- MaxAE

У кожній ітерації всі варіанти з одним значенням r вилучались з навчальної вибірки та використовувались лише для тестування.
